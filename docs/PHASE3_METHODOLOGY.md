# Phase III methods and provenance

Phase III is a presentation layer over verified Phase I preparation and Phase II analysis. It does not train models or recompute hypothesis tests. [Aggregate export builder](../mediscope/visualization/exports.py) verifies prepared-source hashes and Phase II source SHA-256 before writing 19 CSV snapshots. The manifest records source and output checksums. Continuous histograms are bin counts with fixed five- or ten-unit edges; group denominators are recorded. Box plots use Phase II five-number summaries; the Phase III aggregate box whiskers are observed minima/maxima and contain no individual outlier points. Pearson heatmaps reuse Phase II correlation coefficients. The heart pie uses 164/303 and 139/303, so it is a valid single-dataset part-to-whole chart. The local dashboard reads these committed exports, avoiding conflicting statistics.

The Synthea v3.4.0 release JAR was downloaded from the [official release](https://github.com/synthetichealth/synthea/releases/tag/v3.4.0) at `https://github.com/synthetichealth/synthea/releases/download/v3.4.0/synthea-with-dependencies.jar`; SHA-256 `38678aab1e667d26671163824aad60ee5e30fa366f3d59d5ea5765ebb5702432` matched the release asset digest. It was run with seed and clinician seed `424242`, population 10, reference/end date `2024-01-01`, Massachusetts, and `--exporter.clinical_note.export=true`. The JAR's own reported version string was `v3.3.0-96-g17dd17e93`, recorded alongside release v3.4.0. Ten `.txt` notes were generated in `/private/tmp/mediscope_notes/notes` on this Mac; the actual note text is not committed. The combined note-content hash and cleaning policy are recorded in [synthea_note_source.json](../data/metadata/synthea_note_source.json). [notes.py](../mediscope/visualization/notes.py) lowercases/tokenizes text, removes documented stopwords, numeric IDs and template markers, counts terms, and creates a frequency-scaled cloud. The word cloud is a text-frequency visualization, not clinical evidence. The notes came from a **separate** run and are not linked to the existing hospital patient/encounter cohort.

The 31 Phase II PNGs were reviewed in four visual contact sheets and checked for dimensions, titles, axes, denominators, source labels and captions. They show source/units appropriately. Readability issues in the old compact heatmaps, dense monthly timeline, and long-tail encounters-per-patient plot were identified. Phase III adds a larger heatmap and clearer representative histograms, box plots and frequency charts. The old long-tail distribution remains scientifically honest; any focused future view must explicitly state its range. Original Phase II figures and statistical outputs were preserved. Six high-resolution Phase III PNGs and six SVGs are in `reports/figures/phase3/` (including the note cloud). Five report-ready CSVs are in `reports/tables/phase3/`.

Power BI source is generated by [generate_powerbi_project.py](../scripts/generate_powerbi_project.py) using the export schema. Its 32 tables include 19 base exports and 13 disease-scoped views; the dataset dimension links 17 aggregate base tables. Explicit DAX SUM/AVERAGE measures are used for chart values. Six PBIR pages define 29 visual instances. The source project has no local path: `DataRoot` is substituted only in an ignored Windows copy. Static JSON-schema checks were run against Microsoft's published schemas. This cannot verify TMDL import behavior, visuals, filters, theme or PBIX creation in Desktop. Some page outcome slicers currently bind one table and may not cross-filter other views; Desktop review must address this before acceptance.

The Plotly local preview has six sections and uses bundled Plotly.js. Disease outcomes are never combined as one population. Stroke `Unknown` smoking values are reported as unavailable. Diabetes repeated profiles remain retained. Patient and encounter denominators remain separate. Data are for academic research and are not clinically validated.
